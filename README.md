# かじわらタワーバトル　v1.3.1

キャラを積み上げて、**落とした方が負け**のバランス積みゲームです。

**遊ぶ：https://akionlywork-dot.github.io/kajiwara-tower-battle/**

スマホのブラウザ（縦画面）向け。HTML / CSS / JavaScript だけで動き、ビルドは不要です。

---

## 1. 遊び方

### 操作

1. 画面上部にキャラが出ます
2. 画面を指で**左右にドラッグ**して、落とす位置を決めます
3. **「回転」**ボタンで45度ずつ回せます
4. **「落とす」**ボタンで落とします
   （設定で「指を離したら落とす」をONにすると、ドラッグして指を離すだけで落ちます）
5. 全部のキャラが止まったら、次のキャラが出ます
6. 土台から1体でも落ちたらゲーム終了

右上の ❚❚ ボタンでポーズできます。ほかのアプリに切りかえたときも自動でポーズします。

### モード

| モード | ルール |
| --- | --- |
| ひとりで（スコアアタック） | スコア ＝ 積んだ数 × 100点 ＋ 高さ 1m × 100点。ハイスコアに挑戦 |
| たいせん → ともだちと | 1台のスマホを交互に操作。落とした人の負け |
| たいせん → CPUと | CPU（よわい・ふつう・つよい）と交互に積む。CPU は置き方を試算して、強いほど安定する置き方を選ぶ |
| 特殊ルール | 風・傾く土台・つるつる・ジャイアント。ひとりで遊び、ハイスコアはルールごとに記録 |
| たいせん → オンライン対戦 | 2台のスマホで対戦（下記） |

対戦の先攻は、毎回ランダムに決まります（最初に「〇〇 の先攻！」と表示）。

### オンライン対戦

1. 片方が「部屋を作る」を押すと、6桁のルームコードが出る
2. もう片方が「部屋に入る」でそのコードを入力すると、対戦が始まる（先攻は毎回ランダム）

- まず2台を**直接**つなぎます（PeerJS / WebRTC）。Wi-Fi のルーターの設定などで直接つながらないときは、6秒ほどで**公開のメッセージ中継サーバー（MQTT）経由**に自動で切りかえます。中継のときは、少し反応がゆっくりになります
- 中継サーバーは `config.js` の `online.relayBrokers` で変えられます（EMQX・HiveMQ の無料公開サーバーを使用。保証はありません）
- 物理計算は部屋を作った側のスマホだけで行い、相手にはキャラの位置と角度を送っています（2台でズレないように）
- 通信が切れると「接続が切れました」と出てタイトルに戻ります。画面を消したり、ほかのアプリに切りかえたりしても切れます
- 直接つながったときは、お互いのネット上の住所（IPアドレス）が相手の端末に伝わります。中継サーバー経由のときは、ゲームのデータ（キャラの位置・名前）が中継サーバーを通ります。知っている人と遊んでください
- 直接つなぐときは、最初に相手を見つけるためだけに PeerJS の無料公開サーバー（0.peerjs.com）を使います

### 挑戦状

ひとりモード（特殊ルールも）のリザルト画面の「挑戦状を送る」で、友だちに挑戦状の URL を送れます。

- URL を開いた人には「〇〇さんからの挑戦状（1270点）」と出て、**同じ順番のキャラ**・同じルールで挑戦できます
- 終わると「勝ち！」「負け…」が出て、「挑戦状を送り返す」で自分のスコアを入れて送り返せます
- URL の形：`https://.../?seed=12345&mode=solo&rule=wind&score=1270&name=あき`
  （seed＝キャラの順番を決める番号、rule＝特殊ルール、score＝スコア、name＝名前）。
  値がおかしい URL は挑戦状として扱わず、ふつうに始めます
- スマホの共有メニュー（Web Share API）で送ります。使えないブラウザでは、URL とコピーボタンが出ます
- キャラを追加・削除すると、同じ seed でもキャラの順番が変わります（古いバージョンの挑戦状とは順番が合わなくなります）

### リザルトカード・フォトモード

- **リザルトカード**：リザルト画面の「結果を画像でシェア」で、名前・称号・スコア・積んだ数・高さ・モード・タワーの絵・ゲームの URL を1枚の画像にします。
  形は横長（1200×630）と縦長（1080×1350）から選べます。写真アイコンは、載せるかどうかを選べます（初めは載せない設定）
- **フォトモード**：ポーズ画面・リザルト画面の「📷 フォトモード」で、ボタンなどを消して背景とタワーだけを表示します。
  タワー全体が収まるように縮小され、指でドラッグ（移動）・ピンチ（拡大・縮小）して構図を決められます（パソコンはマウスのホイールで拡大）。
  フォトモードの間は、キャラの動きが止まります
- どちらも「シェア」「撮影」で画像を共有します。画像付きで共有できない端末では、画像を保存します

### 高さで変わる背景

タワーが高くなるほど、背景が 草原 → 空 → 雲の上 → 夕焼け → 宇宙 と変わり、新しい背景に届くと「雲の上に到達！」と出ます。
地上の見た目は、プロフィールで選んだ背景（実績で解放するもの）です。区切りの高さと色は `config.js` の `sky` で変えられます（下記）。

### キャラのレア度

キャラにはノーマル（★）・レア（★★）・スーパーレア（★★★）があり、レアほど出にくくなっています。
レア以上が出ると「レア！」「スーパーレア！！」と表示され、キャラが光ります。

### 背景・土台

実績を達成すると、新しい背景（夕焼け・さくら・星空）や土台（石・氷・金）が解放され、プロフィール画面で選べます。

### アプリとしてインストール

- **Android（Chrome）**：設定画面の「アプリとしてインストール」→「インストール」。ホーム画面のアイコンから全画面で起動できます
- **iPhone（Safari）**：画面下の共有ボタン →「ホーム画面に追加」（設定画面の「やり方」でも案内しています）
- 一度開いておけば、通信のない場所でもひとりモードで遊べます（お知らせ・ランキング・オンライン対戦は通信が必要）

### データのバックアップ

設定画面の「書き出す」で、名前・写真・図鑑・実績・戦績・設定・背景などを1つのファイルに保存できます。
機種変更のときは、新しいスマホで「読み込む」からそのファイルを選びます（今のデータは上書きされます）。

### タイトル画面のメニュー

| メニュー | 内容 |
| --- | --- |
| お知らせ | 運営からのお知らせ。新しいお知らせがあると赤い点が付き、起動時にも表示 |
| ランキング | ハイスコアのランキングと、自分のハイスコア・順位 |
| 図鑑 | 一度でも積んだキャラが登録される。全12体 |
| 実績 | 条件を達成すると称号がもらえる |
| 戦績 | プレイ回数・ハイスコア・平均スコア・対戦の勝利数など |
| プロフィール | 名前・アイコン（端末の写真を丸く切り抜き）・称号 |
| ⚙（右上） | BGM・効果音・制限時間・指を離したら落とす |

プロフィール・図鑑・実績・戦績・設定は、遊んでいる端末のブラウザの中だけに保存されます。
写真はどこにも送信されません。
ただし「ランキングに参加」した人だけ、**名前・ハイスコア（スコア・積んだ数・高さ）・端末ごとのランダムな番号**をランキングのスプレッドシートに送ります
（初めてひとりモードを遊んだあとに、送っていいか聞きます。設定画面でいつでもやめられます）。

## 2. キャラの追加方法

1. **画像を用意する**
   背景を透過した画像（PNG または WebP）。余白は自動で無視されます。
   長い辺が 500px 前後だと、きれいに表示されて読み込みも軽くなります。
2. **`images/` フォルダに入れる**
   ファイル名は**半角の英数字と小文字**にします（例：`chara13.png`）。
   公開先（GitHub Pages）は大文字と小文字を区別するので、`Chara13.PNG` のように書くと、
   パソコンでは動いても公開先で読み込めなくなります。
3. **`characters.js` に1行足す**

   ```js
   window.CHARACTERS = [
     { file: "images/chara01.webp", name: "直立", description: "…" },
     ...
     { file: "images/chara13.png", name: "新しいポーズ", description: "図鑑に出る説明文" },  // ← これを足す
   ];
   ```

   | 項目 | 内容 |
   | --- | --- |
   | file | 画像の場所（`images/` から書く） |
   | name | キャラの名前 |
   | description | 図鑑に出る説明文（省略可） |
   | rarity | レア度。`"N"`（ノーマル）/ `"R"`（レア）/ `"SR"`（スーパーレア）。省略すると `"N"` |
   | weight | 出やすさ（省略可）。省略すると config.js の `rarity` のレア度ごとの値（ノーマル10・レア4・スーパーレア1） |
   | size | 画面での大きさ（長い辺の長さ。省略すると 130） |

4. **当たり判定を確認する**
   `hitbox.html` を開くと、全キャラの「本当の輪郭（赤）」と「当たり判定（緑）」が重ねて表示されます。
   緑が赤にほぼ沿っていればOKです。

5. **（必要なら）当たり判定を調整する**

   | 項目 | 使いどころ |
   | --- | --- |
   | `tolerance: 0.5` | 形がズレている → 小さくすると忠実になる（初期値 0.8） |
   | `smooth: 4` | 置いたあとグラグラ揺れ続ける → 指先などの細い出っぱりを削る（3〜5くらい） |
   | `base: 0.08` | 立たせるとグラつく → 足の裏を平らにする範囲を広げる（初期値 0.05、0 で平らにしない） |
   | `hull: true` | それでも安定しない → 輪郭を包む1つの形にする（一番安定。足の間のすき間も埋まる） |

   例：`{ file: "images/chara10.webp", name: "ポーズ10", tolerance: 2, smooth: 4 },`

新しいキャラは、図鑑にも自動で並びます。

## 3. お知らせ・ランキングの更新方法

`data/` フォルダの JSON ファイルを書きかえて GitHub に上げると、遊んでいる人の画面に反映されます。
（古い内容がキャッシュに残って表示されないよう、毎回最新のファイルを読み込むようにしてあります）

### JSON を書くときの注意

- 文字は `"`（半角のダブルクォーテーション）で囲む
- 項目と項目の間は `,`（カンマ）で区切る。**最後の項目の後ろにはカンマを付けない**
- 本文の中で改行したいときは `\n` と書く
- 書き間違えると読み込めなくなり、画面に「取得できません」と出る。
  うまくいかないときは「JSON チェック」で検索して出てくる確認サイトに貼り付けると、間違いの場所がわかる

### お知らせ（`data/news.json`）

```json
{
  "news": [
    {
      "id": 2,
      "date": "2026-11-01",
      "type": "event",
      "title": "ランキング開始！",
      "body": "ハイスコアランキングを始めました。\nタイトル画面の「ランキング」から見られます。"
    },
    {
      "id": 1,
      "date": "2026-10-26",
      "type": "update",
      "title": "かじわらタワーバトル 公開しました",
      "body": "キャラを積み上げて、落とした方が負けのバランスゲームです。"
    }
  ]
}
```

| 項目 | 内容 |
| --- | --- |
| id | 番号。**新しいお知らせほど大きい数にする**（前より大きい id があると「未読」になり、赤い点とポップアップが出る） |
| date | 日付（`年-月-日`）。新しい順に並ぶ |
| type | `"update"`（アップデート）または `"event"`（イベント） |
| title | タイトル |
| body | 本文 |

新しいお知らせは、`"news": [` のすぐ下（先頭）に足すと分かりやすいです。

### ランキング（オンライン）：Google スプレッドシートで自動集計

ひとりモード（ふつうのルール）のハイスコアを自動で集めて、ランキングに表示します。
`config.js` の `ranking.url` が `""` のあいだは、下の `data/ranking.json`（手で書く）のランキングが出ます。

**始め方（最初に1回だけ）**

1. Google ドライブで、新しい**スプレッドシート**を作る（名前は自由。例：「タワーバトル ランキング」）
2. メニューの「拡張機能」→「Apps Script」を開く
3. 最初から書いてある `function myFunction() {...}` を消して、このフォルダの `server/ranking.gs` の中身を**全部**貼り付け、保存（💾）
4. 右上の「デプロイ」→「新しいデプロイ」→ 歯車から「ウェブアプリ」を選び、
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   にして「デプロイ」。Google アカウントの許可を求められたら許可する
   （「このアプリは確認されていません」と出たら「詳細」→「〇〇（安全ではないページ）に移動」）
5. 表示された「ウェブアプリの URL」（`https://script.google.com/macros/s/.../exec`）をコピーし、`config.js` の `ranking.url` に貼る
6. バージョン番号を上げて公開する（「更新を公開する」）

最初のスコアが届くと、スプレッドシートに「ranking」というシートが自動でできます。

**ランキングの管理**

| 列 | 内容 |
| --- | --- |
| id | 端末ごとのランダムな番号（画面には出ない） |
| name / score / count / height / date | 名前・スコア・積んだ数・高さ・記録した日（1人1行。一番いいスコアだけ残る） |
| hidden | **何か書く（例：`x`）と、その人はランキングから消える**。変な名前・ありえないスコアのとき用 |

- 行を消すと、その人の記録は消えます（また遊ぶと、次の自己ベストから載ります）。ずっと出したくない人は、行を消さずに hidden に書いてください
- ありえない値（スコアが「積んだ数・高さ」の計算と合わないなど）は受け付けませんが、本気でズルをする人は防げません。気になる記録は hidden で隠してください
- `server/ranking.gs` を書きかえたときは、「デプロイ」→「デプロイを管理」→ 鉛筆マーク →「バージョン：新バージョン」で更新します（こうすると URL が変わりません。「新しいデプロイ」にすると URL が変わってしまう）
- `config.js` の `score`（配点）を変えたときは、`server/ranking.gs` の `PER_PIECE`・`PER_METER` も同じ数にする

### ランキング（手で書く：`data/ranking.json`）

`config.js` の `ranking.url` が `""` のときに表示されます。今は中身が空です（画面には「ランキングは準備中です」と出ます）。
手で書くときは、次のように書きます。

```json
{
  "updated": "2026-11-01 18:00",
  "ranking": [
    { "rank": 1, "name": "たろう", "score": 2450, "count": 18, "height": 6.5, "date": "2026-10-31" },
    { "rank": 2, "name": "はなこ", "score": 2180, "count": 16, "height": 5.8, "date": "2026-10-30" },
    { "rank": 3, "name": "じろう", "score": 1920, "count": 14, "height": 5.2, "date": "2026-11-01" }
  ]
}
```

| 項目 | 内容 |
| --- | --- |
| updated | 更新日時（画面に「〇〇 更新」と出る） |
| rank | 順位（1〜3位は金・銀・銅で表示） |
| name | 名前 |
| score | スコア |
| count | 積んだ数 |
| height | 高さ（m） |
| date | 記録した日 |

準備中に戻すときは、`"ranking": []` と空にします。

### 実績（`data/achievements.json`）

実績の条件と、もらえる称号を書きます。

```json
{
  "achievements": [
    {
      "id": "stack10",
      "name": "10体積み",
      "title": "積み上げ名人",
      "description": "1回のゲームで10体積んだ",
      "condition": { "type": "count", "value": 10 }
    }
  ]
}
```

- `id` は半角英数字。**一度公開したら変えない**（変えると、達成済みの人も未達成に戻る）
- `condition` の `type` に使えるもの：

| type | 条件 |
| --- | --- |
| `count` | 1回のゲームで value 体積んだ |
| `height` | 1回のゲームで高さが value m に届いた |
| `score` | ひとりモード（ふつうのルール）で value 点以上 |
| `plays` | 合計 value 回遊んだ |
| `totalPieces` | これまでに合計 value 体積んだ |
| `versusWins` | 2人対戦でプレイヤー1（プロフィールの人）が value 回勝った |
| `dexCount` | 図鑑に value 体登録した |
| `dexComplete` | 図鑑を全部登録した（value は不要） |

### 期間限定イベント（`data/events.json`）

お知らせと合わせて、期間中だけ遊べる特殊ルールや、期間中だけ出るキャラを用意できます。
今は空（`"events": []`）なので、何も表示されません。

**1. イベントを書く**（`data/events.json`）

```json
{
  "events": [
    {
      "id": "halloween2026",
      "name": "ハロウィンイベント",
      "start": "2026-10-25",
      "end": "2026-10-31",
      "description": "おばけの特殊ルールと、限定キャラが登場！"
    }
  ]
}
```

| 項目 | 内容 |
| --- | --- |
| id | イベントの名前（半角英数字）。ルールやキャラの `event` に同じものを書く |
| name / description | イベントの名前と説明（メモ。今は画面には出ない） |
| start | 始まる日（`年-月-日`。時刻も決めたいときは `"2026-10-25 18:00"`） |
| end | 終わる日。**その日の終わりまで**開催（時刻を書いたときは、その時刻まで） |

日時は、遊んでいる人のスマホの時計で判定します。

**2. 期間限定にするものに `event` を書く**

- 特殊ルール：`config.js` の `rules` に `event: "halloween2026"` を足す（動きは「特殊ルールを追加する」と同じく `js/rules.js` に書く）。
  期間中だけ特殊ルールの一覧に「期間限定」の札つきで出ます
- キャラ：`characters.js` の行に `event: "halloween2026"` を足す。期間中だけ落ちてきます。
  図鑑には、期間中か、一度積んだことがあるときだけ並びます（図鑑コンプリートの数には入りません）。
  限定キャラは `characters.js` の**一番下**に足してください（図鑑の番号がずれないように）

**3. お知らせを出す**：`data/news.json` に `"type": "event"` のお知らせを足します。

※ 終わったイベントは、`events.json` から消しても、残しておいても大丈夫です（期間外なら何も起きません）。

## 4. 公開する（GitHub Pages）

1. このフォルダを GitHub のリポジトリに上げる（`.gitignore` に書いたファイルは上がらない）
2. リポジトリの **Settings → Pages** で、Branch を `main`、フォルダを `/ (root)` にして Save
3. 数分後に `https://ユーザー名.github.io/リポジトリ名/` で遊べる
4. `index.html` の OGP（`og:url` と `og:image` の2行）には、公開先の完全な URL を書いてある
   （SNS で URL を共有したときに画像を出すには、完全な URL が必要なため）。
   **リポジトリ名を変えたときは、ここも書きかえる**

### 更新を公開する

**プログラムや画像を変えたときは、次の3か所のバージョン番号をそろえて上げます**（スマホに保存された古いファイルが使われ続けないように）。

1. `config.js` の `version`（例：`"v1.3.2"`）
2. `index.html` の `?v=1.3.1` をすべて新しい番号に（エディタの「すべて置換」で）
3. `sw.js` の `VERSION`（例：`"1.3.2"`）

（`data/` のお知らせ・ランキング・実績だけを変えたときは、上げなくて大丈夫です）


ファイルを変更したら、このフォルダでターミナルを開いて次の3行を実行すると、数分後に公開ページに反映されます。

```
git add -A
git commit -m "変更内容のメモ"
git push
```

ほかのファイルはすべて相対パスで書いてあるので、リポジトリ名が何でもそのまま動きます。
`.nojekyll` は、GitHub Pages の変換処理（Jekyll）を止めて、ファイルをそのまま公開するためのものです。消さないでください。

### パソコンで確認するとき

`index.html` をダブルクリックで直接開くと、ブラウザの制限で当たり判定が四角形になり、
お知らせ・ランキングも読み込めません。ローカルサーバー経由で開いてください。

- VS Code の拡張機能「Live Server」で `index.html` を右クリック →「Open with Live Server」
- または、このフォルダでターミナルを開いて `npx serve` を実行し、表示された URL を開く

パソコンの横長の画面では、中央に縦長のゲーム画面が出ます。
スマホの画面で確認したいときは、Chrome の開発者ツール（F12）→ デバイスツールバー（Ctrl+Shift+M）。

## 5. 設定ファイル（`config.js`）

| 項目 | 内容 |
| --- | --- |
| version | バージョン（タイトル画面の右下に表示。今は `v1.3.1`）。更新したら、下の「更新を公開する」の3か所をそろえて上げる |
| devMode | `true` にすると、設定画面に「当たり判定を表示」（開発用）が出る。**公開時は `false`** |
| admin | 管理者モードの合言葉から作った番号（passHash）と、番号を作るときに混ぜる文字（salt） |
| splash | 起動時に出す会社名・表示時間 |
| titleDemo | タイトル画面の背景で積み上がるキャラの順番 |
| score | スコアの配点（1体・1mあたり） |
| turnTimeLimit | 制限時間をONにしたときの、1手の秒数 |
| themes | 背景と土台の種類・色・解放条件（下記） |
| rarity | レア度ごとの名前・出やすさ・色・★の数 |
| cpu | CPU の強さごとの数値（試す置き方の数・選び方・狙いのずれ・考える時間） |
| rules | 特殊ルールの名前・説明・数値（下記） |
| sky | 高さで変わる背景の区切りと色（下記） |
| sounds | 効果音・BGM のファイル（下記） |
| ranking | ランキングを集めるスプレッドシート（Apps Script）の URL（「ランキング（オンライン）」） |

### 背景・土台を追加する

`config.js` の `themes` に1行足します。`unlock` には、解放条件にする実績の id（`data/achievements.json`）を書きます。
`null` なら最初から使えます。

```js
backgrounds: [
  ...
  { id: "ocean", name: "海", unlock: "total100", top: "#2a9df4", bottom: "#bfe9ff", cloud: "#ffffff", ground: "#e8d29a", groundDark: "#cdb57a" },
],
platforms: [
  ...
  { id: "candy", name: "おかしの台", unlock: "score1000", body: "#ff8fb8", top: "#fff0f6", pillar: "#e07aa0" },
],
```

### 高さで変わる背景を追加する

`config.js` の `sky.stages` に1行足します（高さの低い順に並べる）。

```js
sky: {
  blend: 1, // 何 m かけて次の背景の色に変わるか
  stages: [
    { height: 0, name: "草原", icon: "🌱" }, // 地上（色はプロフィールで選んだ背景）
    ...
    { height: 9, name: "宇宙", icon: "🚀", top: "#03051a", bottom: "#1b2156", cloud: "#1b2156", clouds: 0, stars: true },
    { height: 14, name: "月", icon: "🌕", top: "#000000", bottom: "#2a2a40", stars: true }, // ← 足した例
  ],
},
```

- `height` に届くと「〇〇に到達！」と出ます。色は `#` から始まる6桁で書きます
- 書いていない項目（色・雲・星）は、1つ前の背景と同じになります

### 特殊ルールを追加する

1. `config.js` の `rules` に、名前・アイコン・説明・数値を書く
2. `js/rules.js` の `BEHAVIORS` に、同じ名前で動きを書く
   （「キャラの性質を変える」「毎ステップ何かする」「画面に何か描く」などの入口が用意されている。使い方はファイルの先頭に説明あり）

数値だけ変えたいとき（風の強さ・傾く角度など）は、`config.js` を書きかえるだけで済みます。

### 音

`sounds/` フォルダに音声ファイルを置き、`config.js` の `sounds` にその場所を書きます。
`""` のままの音は、プログラムで作った仮の音が鳴ります。

```js
sounds: {
  place: "sounds/place.mp3", // 着地
  fall: "",                  // 落下（"" なら仮の音）
  ...
},
```

- スマホのブラウザは、画面を一度さわるまで音を出せません（起動時のタップで鳴らせるようになります）
- iPhone はマナーモードだと音が鳴りません

### 見た目

`css/style.css` の先頭の `:root { ... }` で、色・フォント・角丸・余白をまとめて変えられます。

## 管理者モード（自分だけのデバッグ用メニュー）

タイトル画面右下のバージョン表示（v1.1.0）を、**3秒以内に7回タップ**すると開きます。合言葉で開いた端末だけが使えます。

| できること | 内容 |
| --- | --- |
| 当たり判定を表示 | キャラの当たり判定の線を表示する |
| 次に出すキャラ | 次に出てくるキャラを固定する（「ランダム」に戻すまで、ずっとそのキャラ） |
| 図鑑・実績 | 全部登録・全部達成、またはリセット（背景・土台の解放の確認に） |
| オンライン対戦の接続 | 待ち受けやつながり方の状態を表示する |
| 称号「開発者」 | 管理者モードの端末でだけ、プロフィールの称号で選べる |
| 管理者モードを終わる | この端末から鍵を消す（次は合言葉が必要） |

### 合言葉の登録（最初に1回だけ）

1. ゲームを開き、タイトル右下のバージョンを7回タップする（合言葉がまだ無いので、登録の画面が出る）
2. 新しい合言葉（8文字以上。ほかで使っていないもの）を入れて「番号を作る」を押す
3. 出てきた1行（`passHash: "…",`）を、`config.js` の `admin` の `passHash: "",` の行と置きかえて、GitHub に上げる
4. もう一度7回タップして、合言葉で開く。開いた端末は、次からは合言葉なしで管理者モードになる

- 合言葉そのものは、どこにも保存されません（config.js には、合言葉から作った元に戻せない番号だけを書きます）。合言葉を忘れたら、同じ手順で新しく登録し直します
- 番号を作る画面は、Live Server（http://127.0.0.1 など）か公開ページ（https）で開いてください（http の別のアドレスでは動きません）
- **注意**：このゲームはファイルを公開しているので、プログラムに詳しい人がブラウザの開発者ツールでプログラムを書きかえれば、こじ開けられます。ふつうに遊ぶ人には開けない、という仕組みです

## 6. フォルダ構成

```
kajiwara/
├── index.html          … ゲームのページ
├── hitbox.html         … 当たり判定チェック用のページ（開発用）
├── config.js           … ゲームの設定
├── characters.js       … ★キャラ一覧（キャラ追加はここ）
├── data/               … ★手で書きかえて更新するデータ
│   ├── news.json       … お知らせ
│   ├── events.json     … 期間限定イベント（今は空）
│   ├── ranking.json    … ランキング（手で書く。ranking.url が空のとき）
│   └── achievements.json … 実績
├── images/             … キャラ画像（WebP）
├── sounds/             … 効果音・BGM（後から置く）
├── css/style.css       … 見た目
├── js/                 … プログラム
│   ├── main.js         … 起動・画面の流れ・ゲームのルール
│   ├── game.js         … ゲーム本体（物理演算・描画・操作）
│   ├── shape.js        … 画像の輪郭から当たり判定を作る
│   ├── ui.js           … 画面の切りかえ・ダイアログ・通知
│   ├── audio.js        … 効果音・BGM
│   ├── settings.js     … 設定の保存
│   ├── save.js         … プレイデータの保存
│   ├── data-file.js    … data/ の JSON を読み込む
│   ├── profile.js / news.js / ranking.js / records.js / dex.js / achievements.js … 各メニュー画面
│   ├── themes.js       … 背景・土台の解放と選択
│   ├── rules.js        … 特殊ルールの動き
│   ├── cpu.js          … CPU対戦の考え方
│   ├── backup.js       … データの書き出し・読み込み
│   ├── challenge.js    … 挑戦状の URL（読み取り・作成）と、共有（共有メニュー・コピー・画像の保存）
│   ├── card.js         … リザルトカード（結果を1枚の画像にする）
│   ├── events.js       … 期間限定イベント（events.json の読み込みと、期間の判定）
│   ├── online.js       … オンライン対戦の通信（直接 / 中継でつなぐ・送る・切れたら知らせる）
│   ├── admin.js        … 管理者モード（合言葉の確認・デバッグ用メニュー）
│   ├── pwa.js          … アプリとしてインストール（Service Worker の登録・インストールボタン）
│   └── hitbox-check.js … hitbox.html の処理
├── server/ranking.gs   … ランキングを集める Google Apps Script（スプレッドシートに貼り付けて使う）
├── lib/                … ライブラリ（物理演算 Matter.js 0.19.0・poly-decomp 0.3.0、通信 PeerJS 1.5.4・mqtt.js 5.10.1）
├── manifest.webmanifest … アプリとしてインストールするための設定（名前・アイコンなど）
├── sw.js               … Service Worker（ファイルを保存して、アプリとして・通信なしでも起動できるように）
├── icons/              … アプリのアイコン（192px・512px・マスカブル）
├── favicon.svg         … ブラウザのタブのアイコン
├── apple-touch-icon.png … iPhone のホーム画面のアイコン
├── ogp.png             … SNS で共有したときの画像（1200×630）
├── .gitignore          … GitHub に上げないファイルの一覧
└── .nojekyll           … GitHub Pages でファイルをそのまま公開するための印
```

`_source/images/` には、キャラ画像の元データ（PNG）が入っています。`.gitignore` で除外しているので公開はされません。
